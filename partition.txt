
2 what is partitioning in distributed systems?
ans partitioning in distributed systems is the process of dividing a large dataset into smaller, more manageable pieces and distributing them across multiple nodes in a network.
partitioning is used to improve the performance and scalability of distributed systems by allowing multiple nodes to process data in parallel.

3 type of partitioning
ans vertical partitioning
this form of partitiioning mainly comes from relation database where we partitiion data or table to multiple table with fewer columns and 
then we can store this multiple table to different node

dis
we have to get the data from the multiple node to complete the data we use very complex join statement that reduce efficency of the system

horizontal partitioning
this form of partitioning is mainly used in distributed database where we divide data into multiple parts and store it to different node
dis
we may still have to search for multiple node to get the data we need because the data range of search query may be in different node 

trade off
in partitioning there is always of a trade off between the consistency of data because it is very to perform atomic operation in distributed system

type of partitioning
1 range 
1 this is the most basic one in this we split dataset in range according to the value of the specific column and we then store 
  each split in different node of course some central system or master node maintain a list of all the range and map which node store 
  specific range 

advantages
1 it is very easy to implement
2 it is very easy to maintain
3 it is very easy to scale
4 it is very easy to perform query
5 it is easy to resize we can increase one range and decrease the other range and reexchange between data in very less
6 good performance on the range query for the partition key 
disadvantages
1 inability to perform a range query other then partition key 
2 it is not good for the data that is not evenly distributed
3 bad performance on the range query for the partition key when the range is very big 

hashing partition
in this type of partition we use specific hash function on the specific attribute of the data to decide which data go at which node or server 
formula usually is hash(key)%N
advantages
1 easy to implement
2 if hash function is good it high change we divide the data uniformly  
disadvantages
1 if added or removed a node or server then the massive mapping or allocation of data will happen 


consistent hashing 
in this type of partition assume that we place server or node in round circle using the hash function and same for the data key then we pass the 
request to nearest server to the right 
but there may be some issue of load imbalance to overcome we use virtual node or server which means we use different hash function on the same server or node 
due to this we can have more position of same sever in ring or circle 
disadvantages
1 it is hard to implment 
2 if we do not use the virtual node there may high chance of load imbalance
advantages 
1 it make shuffling of data less 
2 fault tolerance even if some node goes down next nearest node take over 
3 scalability high due to fault tolerance
